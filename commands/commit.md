# commit

Проанализируй staged-изменения и создай один хорошо сформулированный коммит в
стиле Conventional Commits.

## Шаги

1. Посмотри, что застейджено: `git diff --cached`. Если пусто — сообщи и
   предложи `git add`.
2. Определи тип: `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `chore`.
3. Составь заголовок `<тип>(<scope>): <суть>` ≤ 72 символов, в повелительном
   наклонении.
4. При необходимости добавь тело: что и почему (не «как»).
5. Покажи сообщение пользователю и закоммить после подтверждения.

Доп. указания: `$ARGUMENTS`.

## Результат

Один коммит с понятным сообщением; вывод `git log --oneline -1`.
