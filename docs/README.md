# docs

Заметки по best practices: как писать хорошие скиллы, агентов, команды, хуки и
MCP-конфиги, плюс общие рабочие приёмы.

## Содержание

- [`best-practices.md`](best-practices.md) — рекомендации по каждому типу элемента.

## Принципы коллекции

1. **Один элемент — одна ответственность.** Скилл/агент/команда решают одну
   чёткую задачу.
2. **Имена в kebab-case.** Совпадают между файлом, frontmatter и `catalog.json`.
3. **Описание = триггер.** Поле `description` объясняет, *когда* подключать
   элемент, а не только что он делает.
4. **Реестр актуален.** После добавления элемента обнови `catalog.json`.
