# Паттерны проектирования агентов

Практические паттерны для создания эффективных агентов в коллекции.

## Основные паттерны

### 1. Specialist Agent (специалист)
Агент с глубокой экспертизой в одной области. Оркестратор делегирует задачу
целиком, агент возвращает полный результат.

Пример: `code-reviewer`, `security-auditor`.

Ключ: узкий scope, единственная ответственность, ясный формат вывода.

### 2. Pipeline Stage (этап конвейера)
Агент — один шаг цепочки. Получает вывод предыдущего агента, обрабатывает,
передаёт следующему.

Пример: `test-writer` (после `code-reviewer`).

Ключ: ясный INPUT и OUTPUT формат, идемпотентность.

### 3. Facilitator (фасилитатор)
Агент не производит артефактов, а ведёт процесс — задаёт вопросы, структурирует
информацию, принимает решения.

Пример: `sprint-retro-facilitator`, `incident-commander`.

Ключ: не делает за пользователя, задаёт вопросы по одному.

### 4. Reviewer (ревьюер)
Анализирует артефакт и возвращает приоритизированные находки, не переписывая.

Пример: `code-reviewer`, `accessibility-reviewer`.

Ключ: severity у каждой находки, конкретное место (`файл:строка`).

## Чего избегать

- Агент, делающий одновременно две несвязанных вещи → split на два.
- Системный промпт без ограничений → агент будет делать что угодно.
- «Помогающий» тон вместо экспертного → потеря точности.
- Мёртвые инструкции («всегда думай творчески») → убирать.

## Формат description — ещё раз

```
Делегируй, когда <триггер>. Делает <что>. Не делает <что не входит>.
```

Первое предложение — условие делегирования. Это главное.
