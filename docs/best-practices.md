# Best practices

Краткие рекомендации по наполнению коллекции.

## Скиллы

- Папка с `SKILL.md`; `name` совпадает с именем папки.
- `description` начинай с триггера: «Use when the user wants to …».
- Держи тело компактным; тяжёлые ресурсы — в отдельных файлах внутри папки.
- Скилл должен быть самодостаточным и не дублировать другие скиллы.

## Агенты

- `description` отвечает на вопрос «когда делегировать задачу этому агенту».
- Системный промпт задаёт роль, принципы, ограничения и формат вывода.
- Избегай пересечения зон ответственности между агентами.

## Команды

- Имя файла = имя команды (`deploy.md` → `/deploy`).
- `description` короткий и конкретный — он виден в списке команд.
- Используй `$ARGUMENTS` для параметров вызова.

## Хуки

- Читай событие из stdin (JSON), управляй поведением кодом возврата.
- `exit 2` блокирует действие и возвращает stderr модели.
- Делай скрипты идемпотентными и быстрыми, особенно `SessionStart`.

## MCP

- Никаких секретов в репозитории — только `${ENV_VAR}` подстановки.
- Один файл на сервер, имя файла = имя сервера.

## Общее

- kebab-case везде, единообразие имён.
- После добавления элемента обнови `catalog.json`.
- Пиши README в каждой папке, чтобы коллекция оставалась навигируемой.
