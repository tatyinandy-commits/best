# code-review-checklist

> Назначение: персональный чек-лист для ревью чужого кода — чтобы ничего не
> пропустить и давать систематическую обратную связь.
> Теги: #review #process #quality

## Контекст

Используй как базу для ревью PR — пройди по каждому разделу перед отправкой
комментариев.

## Промпт

```
Помоги отревьюить PR систематически. Пройдём по секциям:
1. Корректность: есть ли баги, гонки, утечки, неверная обработка ошибок?
2. Безопасность: инъекции, небезопасные дефолты, секреты в коде?
3. Тесты: покрыты ли краевые случаи, детерминированы ли тесты?
4. Дизайн: правильный уровень абстракции, нет ли дублирования?
5. Читаемость: понятны ли имена, нужны ли комментарии?
6. Производительность: есть ли очевидные проблемы (N+1, лишние копии)?
7. Обратная совместимость: не сломает ли это клиентов/окружения?
Давай по каждому разделу: ok / находки с severity. В конце — вердикт.
```

## Заметки

Уровни severity: blocker (нельзя мёрджить) / major (нужно исправить) /
minor (желательно) / nit (по желанию).
