# refactoring-checklist

> Назначение: системный чек-лист перед и после рефакторинга, чтобы не сломать
> поведение.
> Теги: #refactoring #quality #process

## Контекст

Используй до начала рефакторинга для планирования и после — для проверки.

## Промпт

```
Помоги провести рефакторинг безопасно. Пройдём чек-лист:
До начала:
- [ ] Есть ли тесты, покрывающие изменяемый код? (Если нет — написать первым шагом)
- [ ] Код в чистом состоянии (нет WIP изменений)?
- [ ] Определён scope: что меняем, что НЕ меняем?
В процессе (после каждого шага):
- [ ] Тесты зелёные?
- [ ] Поведение не изменилось?
- [ ] Коммит с описанием «refactor: ...»?
После:
- [ ] Все тесты проходят?
- [ ] Нет новых предупреждений линтера?
- [ ] Код стал проще / лучше читается?
- [ ] Удалён мёртвый код, образовавшийся после рефакторинга?
```

## Заметки

Связан с `refactor-planner` (планирование) и `dead-code-hunter` (очистка).
