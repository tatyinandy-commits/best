# dividend-reconcile

## Назначение

Проверка корректности распределения дивидендов по долям (tokenized shares).

## Инварианты распределения

1. **Сохранение суммы:** `Σ выплат всем держателям == объявленный дивиденд`
   (с учётом детерминированной обработки остатка/dust).
2. **Snapshot-консистентность:** доля считается от баланса на момент snapshot,
   а не текущего — иначе перевод после объявления ломает учёт.
3. **Защита от double-claim:** держатель не может получить выплату дважды за один
   период (флаг `claimed[period][holder]` или pull-паттерн с учётом).
4. **Переводы между snapshot и claim:** право на дивиденд привязано к snapshot,
   не «переезжает» с токеном (или переезжает — но согласовано с контрактом).

## Сверка on-chain ↔ off-chain

- Сумма начисленного в БД == сумме `Transfer`/`DividendPaid` событий в контракте.
- Баланс пула выплат покрывает объявленные, но не выплаченные дивиденды.
- Нет «осиротевших» начислений без on-chain подтверждения.

## Тест-кейсы

- Держатель перевёл всю долю до snapshot → 0 выплаты.
- Держатель купил долю после snapshot → 0 выплаты за этот период.
- Сумма по всем держателям с округлением вниз + dust == объявленному.
- Повторный claim → отклонён.

## Формат вывода

Проверенные инварианты (ok/нарушено) + расхождения on-chain/off-chain + тест-кейсы.
