# onchain-event-index

## Назначение

Надёжная индексация событий блокчейна в БД с устойчивостью к реоргам и сбоям.

## Ключевые проблемы и решения

### Reorg (откат блоков)
- Не считай блок финальным сразу — жди N подтверждений (на Base обычно
  достаточно небольшого N, но учитывай требования к финальности).
- Храни `block_hash` вместе с `block_number`; при индексации проверяй, что
  родительский хэш совпадает — иначе откати записи изменённых блоков.

### Пропущенные блоки / сбой индексатора
- Храни `last_indexed_block` как курсор; при рестарте продолжай с него.
- Идемпотентность: уникальный ключ `(tx_hash, log_index)` — повторная
  обработка не создаёт дубли (`INSERT ... ON CONFLICT DO NOTHING`).

### Полнота
- Запрашивай логи диапазонами (`eth_getLogs` с `fromBlock`/`toBlock`),
  учитывай лимиты RPC на размер диапазона/ответа.
- Обрабатывай rate limits RPC с backoff (см. скилл `rate-limit-debug`).

### Сверка on-chain ↔ off-chain
- Периодически сверяй: баланс/supply в БД == значение из контракта (`balanceOf`).
- Расхождение → алерт + повторная индексация затронутого диапазона.

## Чек-лист

- [ ] Курсор последнего блока персистентен.
- [ ] Уникальный ключ на (tx_hash, log_index).
- [ ] Обработка реоргов через block_hash.
- [ ] Ожидание подтверждений перед «финализацией» данных.
- [ ] Периодическая сверка с on-chain состоянием.

## Формат вывода

Диагностика индексатора по чек-листу + предложения по устранению пробелов.
