# release-checklist

## Назначение

Проверка готовности к релизу по чек-листу перед публикацией версии.

## Когда использовать

- Подготовка нового релиза/тега.
- Нужно убедиться, что ничего не забыто перед публикацией.

## Чек-лист

1. Ветка чистая, синхронизирована с основной: `git status`, `git pull`.
2. Версия поднята по semver во всех нужных местах (манифест, константы).
3. CHANGELOG обновлён (см. скилл `changelog-from-commits`).
4. Тесты и линтеры зелёные; сборка проходит.
5. Зависимости проверены (см. скилл `dependency-audit`).
6. Документация и примеры актуальны.
7. Тег создан: `git tag -a vX.Y.Z -m '...'` и запушен.
8. Артефакты собраны/опубликованы; релиз-ноты оформлены.

## Формат вывода

Отчёт по каждому пункту: ✅/❌ и что осталось сделать перед релизом.

## Заметки

Ничего не публикуй без подтверждения — выдай статус и список блокеров.
